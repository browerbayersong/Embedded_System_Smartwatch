# 嵌入式项目硬件配置介绍（STM32F103 智能手表）

## 一、系统概述

- **MCU 型号**: STM32F103C8T6（Cortex-M3 内核，72 MHz 主频）
- **系统架构**: 基于 STM32CubeMX + HAL 库框架
- **总线时钟**: APB1 = 36 MHz，APB2 = 72 MHz（TIM2 输入时钟 = 72 MHz）

## 三、中断配置

### 3.1 中断优先级（NVIC）

| 中断源 | 抢占优先级 | 子优先级 | 功能 |
|--------|-----------|---------|------|
| **DMA1_Channel6** (USART2 RX) | 0 | 0 | 蓝牙接收 DMA |
| **DMA1_Channel7** (USART2 TX) | 0 | 0 | 蓝牙发送 DMA |
| **TIM2** | 5 | 0 | 1Hz RTC 时钟节拍 |
| **USART2** | 5 | 0 | 蓝牙串口通信 |
| **EXTI9_5** (PA6, PB13) | 6 | 0 | 旋转编码器 & 按键 |
| **SysTick** | 默认 | 默认 | HAL 时基（1ms） |

### 3.2 EXTI 外部中断处理

`EXTI9_5_IRQHandler()` 位于 [`stm32f1xx_it.c:251`](file:///d:/Project/Embedded_System_Design/Class_Project/Embedded_System_Smartwatch/Phase3_Bluetooth/Core/Src/stm32f1xx_it.c#L251-L292)，处理两个事件：

- **PA6（CLK 触发）**：读取 PA7（DT）的状态判断旋转方向
  - `CLK != DT` → 顺时针（下一页，`encoder_delta++`）
  - `CLK == DT` → 逆时针（上一页，`encoder_delta--`）
- **PB13（SW 按键）**：下降沿触发，置 `encoder_sw_pressed = 1`

### 3.3 其他中断

- **SysTick_Handler** ([`stm32f1xx_it.c:188`](file:///d:/Project/Embedded_System_Design/Class_Project/Embedded_System_Smartwatch/Phase3_Bluetooth/Core/Src/stm32f1xx_it.c#L188-L197))：HAL 时基，每 1ms 调用 `HAL_IncTick()`
- **DMA1_Channel6_IRQHandler / Channel7_IRQHandler**：DMA 传输完成中断，调用 HAL DMA 处理
- **USART2_IRQHandler**：UART 事件中断（空闲、错误等）
- **HardFault_Handler** 等异常处理：死循环等待调试

## 四、定时器配置（TIM2）

位于 [`tim.c:28`](file:///d:/Project/Embedded_System_Design/Class_Project/Embedded_System_Smartwatch/Phase3_Bluetooth/Core/Src/tim.c#L28-L71)，TIM2 用作 **RTC 时钟节拍定时器**：

| 参数 | 值 | 计算 |
|------|-----|------|
| **输入时钟** | 72 MHz | APB1 预分频器 = 2 → TIM 时钟 = 36 × 2 |
| **PSC (预分频)** | 7199 | 72 MHz / 7200 = **10 kHz** |
| **ARR (自动重载)** | 9999 | 10 kHz / 10000 = **1 Hz** |
| **计数模式** | 向上计数 | 溢出时产生更新事件 |
| **URS** | 仅计数器溢出 | 避免手动 UG 产生额外中断 |
| **中断频率** | **1 Hz** | 每秒产生一次更新中断 |

### 4.1 中断处理

`TIM2_IRQHandler()` ([`stm32f1xx_it.c:297`](file:///d:/Project/Embedded_System_Design/Class_Project/Embedded_System_Smartwatch/Phase3_Bluetooth/Core/Src/stm32f1xx_it.c#L297-L343)) 实现了**软件 RTC**：

```
秒 → 分 → 时 → 星期 → 日 → 月 → 年
包含闰年判断逻辑（%4==0 && %100!=0 或 %400==0）
```

启动函数：`MX_TIM2_Start()` — 置位 `TIM_CR1_CEN` 位，启动计数器。

> 💡 **设计要点**：TIM2 采用**直接寄存器编程**而非 HAL 函数，这是为了更精确地控制 URS 位（只由溢出产生更新中断），避免 HAL 自动设置的其他行为带来的误差。

## 五、串口配置（USART2）

位于 [`usart.c:33`](file:///d:/Project/Embedded_System_Design/Class_Project/Embedded_System_Smartwatch/Phase3_Bluetooth/Core/Src/usart.c#L33-L59)，USART2 用于 **HC-05 蓝牙模块**通信：

| 参数 | 值 |
|------|-----|
| **波特率** | 115200 |
| **数据位** | 8 bit |
| **停止位** | 1 bit |
| **校验位** | None |
| **流控** | None |
| **模式** | Tx + Rx |
| **过采样** | 16x |

### 5.1 DMA 配合 USART2

为了提高通信效率并减少 CPU 开销，USART2 使用 **DMA** 进行数据传输：

| DMA 通道 | 方向 | 模式 | 数据对齐 |
|----------|------|------|----------|
| **DMA1_Channel7** (TX) | 内存 → 外设 | NORMAL（单次） | 字节 |
| **DMA1_Channel6** (RX) | 外设 → 内存 | **CIRCULAR**（循环） | 字节 |

**特点**：
- **发送 (TX)**：普通模式，CPU 发起一次传输后由 DMA 完成，传输完成触发中断。
- **接收 (RX)**：**循环模式** — DMA 持续将接收到的数据写入环形缓冲区，永不停止，CPU 只需定期检查即可，避免数据丢失。

DMA 初始化位于 [`dma.c:39`](file:///d:/Project/Embedded_System_Design/Class_Project/Embedded_System_Smartwatch/Phase3_Bluetooth/Core/Src/dma.c#L39-L53) 的 `MX_DMA_Init()`。

## 六、总线配置（I2C1 & I2C2）

位于 [`i2c.c:31`](file:///d:/Project/Embedded_System_Design/Class_Project/Embedded_System_Smartwatch/Phase3_Bluetooth/Core/Src/i2c.c#L31-L87)，项目使用 **两路独立 I2C 总线**，避免外设地址冲突：

### 6.1 I2C1 — OLED 显示屏

| 参数 | 值 |
|------|-----|
| **引脚** | PB6 (SCL)、PB7 (SDA) |
| **时钟速度** | 100 kHz（标准模式） |
| **占空比** | 2:1 (I2C_DUTYCYCLE_2) |
| **寻址模式** | 7-bit |
| **自身地址** | 0（主机模式） |
| **引脚模式** | AF_OD（复用开漏输出） |

> OLED 屏 I2C 地址通常为 `0x78` 或 `0x3C`

### 6.2 I2C2 — MPU6050 六轴传感器

| 参数 | 值 |
|------|-----|
| **引脚** | PB10 (SCL)、PB11 (SDA) |
| **时钟速度** | 100 kHz |
| **占空比** | 2:1 |
| **寻址模式** | 7-bit |
| **引脚模式** | AF_OD |

> MPU6050 I2C 地址通常为 `0xD0`（AD0=0）或 `0xD2`（AD0=1）

### 6.3 I2C 设计要点

1. **开漏输出**：I2C 总线需要开漏（OD）输出配合外部上拉电阻（通常 4.7kΩ），这是 I2C 协议的标准要求。
2. **双总线分离**：OLED 和 MPU6050 各占一路 I2C，避免总线竞争和地址冲突，提升稳定性。
3. **标准模式**：100 kHz 为 I2C 标准模式，兼容性好，对于 OLED 显示和 IMU 数据读取来说速度足够。

## 七、引脚分配总览图

```
STM32F103C8T6 (48 pins)
├─ GPIOA
│  ├─ PA2 → USART2_TX (HC-05 Bluetooth)
│  ├─ PA3 → USART2_RX (HC-05 Bluetooth)
│  ├─ PA6 → 旋转编码器 CLK (EXTI 双沿)
│  └─ PA7 → 旋转编码器 DT (普通输入)
├─ GPIOB
│  ├─ PB0  → HC-05 STATE 信号 (检测连接状态)
│  ├─ PB6  → I2C1_SCL (OLED)
│  ├─ PB7  → I2C1_SDA (OLED)
│  ├─ PB10 → I2C2_SCL (MPU6050)
│  ├─ PB11 → I2C2_SDA (MPU6050)
│  └─ PB13 → 旋转编码器 SW (EXTI 下降沿)
└─ 定时器
   └─ TIM2 → 1Hz RTC 节拍
```

## 八、关键设计亮点

1. **旋转编码器采用 EXTI 中断**（双沿触发 PA6），无需轮询，响应灵敏
2. **TIM2 寄存器级编程**实现精确 1Hz 软件 RTC，避免 HAL 抽象层的不确定性
3. **USART2 + DMA** 实现蓝牙通信的零 CPU 干预，尤其是接收端的循环 DMA 防止数据丢失
4. **双 I2C 总线** 将 OLED 显示和 MPU6050 传感器分离，提升系统稳定性
5. **中断优先级分层**：DMA 最高（0）→ TIM/UART 中等（5）→ 用户输入最低（6），确保实时性
